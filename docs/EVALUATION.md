# Batch SFT & Evaluation (Google Colab + Qwen3-0.6B)

All commands assume `cwd=/content/llm-reasoning-optimization`, Google Drive mounted and the package installed with `pip install -e '.[training]'`.

## 1. Train multiple models

Create a distinct JSON configuration for each SFT experiment. For instance, `configs/sft.json` (rank 8) and `configs/sft_r16.json` (rank 16). Each run **starts from the original pretrained Qwen**, not the previous adapter. The dataset, validation split, epochs, effective batch size and seed are identical in these two example configs. Every finished run creates a new timestamped directory on Drive containing an `adapter/` and `summary.json`.

```bash
python -u -m reasoning_opt.training.batch --config configs/sft_batch.json --preflight-only
python -u -m reasoning_opt.training.batch --config configs/sft_batch.json
```

The batch runner operates sequentially; it **does not** train when you merely create a JSON file. Running it again **retrains both experiments**, generating new timestamped runs. Only add a config to `configs/sft_batch.json` if you want to train it now.

## 2. Development validation (select model / hyperparameters)

```bash
python -u -m reasoning_opt.evaluation.dev --config configs/evaluation.json
```

This generates completions from **held-out GSM8K validation questions** (default 100, up to 200); measures strict numeric final-answer accuracy, generation length, reasoning length, and malformed thinking / parsing rates. The original base model is scored once and reused for future adapter comparisons. This is deliberately **not** BottleCap SVAMP and **not** the official benchmark. Results go to `MyDrive/llm-reasoning/evaluations/development/.../{summary.csv,summary.json}` and individual `records.jsonl`.

Runs are selected via `experiment_names` in `configs/evaluation.json`: empty list `[]` means all finished experiments with saved `adapter` and `summary.json`; otherwise list exact folder names (including timestamp), e.g. `"gsm8k-sft-r8-20261009-165120"`.

Model decoding for development validation is **greedy** (`do_sample=False`), for quick reproducible checks. Its accuracy is therefore a development metric and not directly comparable to BottleCap's official sampling recipe.

Do not select hyperparameters from official BottleCap test scores. Use the GSM8K held-out set and optionally a separate development set for other domains.

## 3. BottleCap official pipeline (smoke, preliminary, final)

Install the upstream evaluation dependencies in Colab (heavy, may take time and change the Python environment):

```bash
python -m pip install -r external/ThinkingCap-Test/requirements.txt vllm==0.23.0
```

The frozen BottleCap source is stored under `external/ThinkingCap-Test`, and our runner generates `evaluate_t4.py` from a **copy** of the official evaluator with only the `LLM(...)` initialization changed to `dtype="half", attention_backend="TRITON_ATTN"`. This uses the explicit supported vLLM 0.23 API, not the deprecated/ignored `VLLM_ATTENTION_BACKEND` env var. The original scorer, question prompts, seeds, decoding and `compare.py` remain unchanged.

Edit `configs/evaluation.json` `benchmark` section:

- Smoke only: `{"mode": "smoke", "benchmarks": ["svamp"], "samples": 1}` (5 questions per requested benchmark; **no valid scores**).
- Preliminary *test* run: `{"mode": "benchmark", "benchmarks": ["svamp"], "samples": 1}` (1,000 SVAMP questions × 1 generation; **not** official full recipe, avoid using to tune models).
- Official full run: `{"mode": "benchmark", "benchmarks": ["svamp", "bfcl", "mbpp", "ifeval"], "samples": 8}` (2,759 questions × 8 generations **per model**, expensive on T4).

```bash
python -u -m reasoning_opt.evaluation.benchmark --config configs/evaluation.json
```

A **single command** benchmarks the original Qwen and each finished LoRA adapter sequentially. The script calls the genuine upstream `compare.py` for each model with paired generations and confidence intervals. Benchmark questions are downloaded and cached to `MyDrive/llm-reasoning/evaluations/_questions` (pinned by the BottleCap scripts). Results appear under `evaluations/bottlecap/{mode}-{profile-hash}/` with per-model records, summary, comparisons, logs.

Changing evaluation settings produces a separate profile directory. Reruns reuse already finished results with matching model/adapter SHA-256; incomplete results are **never** silently overwritten. Investigate an incomplete folder before retrying. `--smoke` does not include statistically usable metrics.

**Security:** MBPP+ grades executable code generated by the model. On Colab, bubblewrap may be unavailable, and BottleCap falls back to resource limits only, not a sandbox with filesystem/network isolation. Use a disposable trusted runtime, or exclude MBPP+ until appropriate isolation is available. See upstream `utils/eval/sandbox.py`.

## 4. What to read

- SFT: `experiments/<run-id>/summary.json`, `metrics.jsonl`, `train.log`, `adapter/`
- Dev validation: `evaluations/development/gsm8k-<hash>/summary.csv` and `records.jsonl`
- Official: `evaluations/bottlecap/benchmark-<hash>/summary.csv`, `comparisons/<run-id>.json`, `models/<run-id>/records.jsonl`

*Important:* saving adapters directly to Google Drive is robust against Colab disconnections but can slow checkpointing. Later we can add local workdir + backup after each checkpoint.
